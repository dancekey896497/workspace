**6．结论：保留 O_DIRECT 时，最小替代是“快照 → worker 内对齐 staging → 完整写检查”；无需禁止 bytes 作为中间快照。**

依据：`bytes()` 可以隔离后续池复用，但不能保证最终系统调用地址对齐。针对照片已有快照修改，可只替换同步写 helper：

```python
import ctypes
import errno
import mmap
import os

def write_direct(tmp_path, snapshot, mem_align, offset_align):
    n = len(snapshot)
    if mem_align <= 0 or offset_align <= 0 or n == 0 or n % offset_align:
        raise ValueError("invalid DIO alignment/length")

    with mmap.mmap(-1, n + mem_align - 1) as owner:
        base = ctypes.addressof(ctypes.c_char.from_buffer(owner))
        start = (-base) % mem_align
        with memoryview(owner)[start:start + n] as buf:
            buf[:] = snapshot
            fd = os.open(tmp_path, os.O_CREAT | os.O_WRONLY |
                         os.O_TRUNC | os.O_DIRECT, 0o644)
            try:
                written = os.write(fd, buf)
                if written != n:
                    raise OSError(errno.EIO, f"short write: {written}/{n}")
            finally:
                os.close(fd)
```

必要条件：

- `mem_align/offset_align` 来自目标文件已核实的要求，不能默认填 4096。
- 源 reservation 覆盖快照复制；staging 分配、写入、释放都在同步 worker 内。
- helper 正常返回才 rename；短写直接失败，不发布文件。
- 临时路径不能被并发写者共用。
- 这是写侧核心改动，读侧仍需完整读和 copy-back。**目标 Linux/Ascend 可用性未核实**。

当 fd 使用 O_DIRECT、目标文件有内存对齐要求时，必须保证**最终传入的地址**符合要求。可信 allocator 可以建立统一契约；任意 bytes、切片或续写地址不能免检。buffered I/O 不受该 DIO 约束；未知要求不能当成无要求。[open(2)](https://man7.org/linux/man-pages/man2/open.2.html)、[statx(2)](https://man7.org/linux/man-pages/man2/statx.2.html)。
