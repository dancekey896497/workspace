# 给黄区 Agent 的启动提示

**结论：你的任务是验证并准备 Ascend 内存兼容性最小修复。请先读同目录《01_完整操作指南.md》，按阶段执行并按《02_文本回传模板.md》回传；不要要求用户传原始文件。**

故事背景：我们维护 LMCache-Ascend。现场报告某类 `aclrtMallocHost` 主机内存直接交给 O_DIRECT 文件读写时失败，普通内存中转后恢复。原主库 PR #5687 已按用户要求关闭。现在评估 #174 的思路：先申请普通 host 内存，再注册给 NPU，使实际缓存内存同时适用于设备和文件读写，避免所有平台每次都增加中转复制。

本轮只处理 Ascend 内存兼容性及新申请方式自身必要的注册、失败清理、配套释放。短写检查、旧临时文件截断、异步取消协议、性能优化、主库重构均暂缓。原中转候选保留作记录；不要把它当成本轮要重新提交的补丁。

工作要求：

1. 自行发现容器、Python、源码、已加载原生库、CANN/驱动、设备和缓存挂载；文档里的路径只是历史线索，不是当前事实。
2. 先只读确认并直接测试旧 allocator 的内存。已有 FS staging 可能掩盖故障，不能用“服务成功”替代直接内存对照。
3. 使用专用实验目录、相同挂载上的新文件，所有 native 修改和构建只发生在隔离源码目录。保留现场现有代码与运行服务。
4. 不升级依赖，不覆盖安装包，不切生产分支，不清空缓存，不停已有服务，不上传、不创建/重开 PR。
5. 只有基线、普通内存对照与调用路径已明确，才移植 #174 的必要思路；不要直接 cherry-pick 旧 PR，它可能目录冲突且存在待核对分支。
6. 候选必须保留公共 Python 入口，匹配申请与释放方式；必须判断 register 成功、失败、抛异常各路径由谁清理。保留其他设备原有行为，本轮重点是实际 910B 路径。
7. 隔离构建后，在全新进程确认原生库来自候选目录。用 `probe_memory.py` 验证真实 native 内存、文件直接读写及 NPU→host→文件→host→NPU 的 API 往返。
8. 探针 API 往返不能证明真实连接器的映射算子、严格页缓存绕过或零拷贝。还要在隔离 MP 服务中覆盖实际连接器；旧 FS staging 与新 allocator 不能同时混改而不留对照。
9. 若没有空闲设备/源码/构建依赖，保留已完成结果并回传明确卡点。不要将硬件缺失写成通过，不要切成 CPU 模拟代替现场结论。
10. 结果先给结论，再给依据；未知写“未核实”。回传具体数值、关键日志、实际路径和最终 diff 文本。原始数据留在黄区，不要求文件传输。

执行前先输出本地发现表和阶段安排，然后继续无需追问即可开展的步骤。仅在确实无法从本机发现的缺项、现有任务冲突或会影响生产服务的操作需要额外授权时停在相应边界；不要反复索取已有信息。

最终需回答：①哪个实际入口分配了 FS L2 使用的内存；②旧 native 直接 I/O 与普通 mmap 对照如何；③新 native 注册后的同一缓冲是否通过；④NPU 功能链与真实 MP 入口是否通过；⑤申请/注册/释放是否配套；⑥修改适用范围与未核实项。

用户若只能贴一份长文本：请读取《01_完整操作指南.md》，其附录已包含完整探针，可以自行保存为 `probe_memory.py`。本提示为任务摘要，不替代完整指南。
