## 2. 三处必须直接订正

### 2.1 第 48、50、54 行：statx 掩码判断反了

**结论：改为“返回掩码不含 DIOALIGN，本次未取得 DIO 对齐信息”。**

依据：Linux UAPI 定义 `STATX_DIOALIGN = 0x00002000U`，`STATX_MNT_ID = 0x00001000U`。[Linux v6.6 stat.h](https://github.com/torvalds/linux/blob/v6.6/include/uapi/linux/stat.h)

```text
返回的 stx_mask        = 0x17ff
STATX_DIOALIGN         = 0x2000
0x17ff & 0x2000        = 0
是否包含 DIOALIGN      = False
```

本轮已独立计算。`0x17ff` 中的 `0x1000` 是 MNT_ID，不是 DIOALIGN。这里假定文中 mask 是正确读出的返回字段 `stx_mask`；探针本身是否正确声明了结构体、打印了正确字段，未核实。

字段有效性由返回 mask 标示。缺少对应位时，看到 `mem_align=0、offset_align=0`，不能解释为“已支持但返回零”，也不能解释为“该文件不支持 O_DIRECT”或“无需对齐”。准确结论仅是**这次查询未提供该信息**。[Linux statx(2)](https://man7.org/linux/man-pages/man2/statx.2.html)

建议直接替换 C 组：

> 对实际缓存文件的 statx 查询返回 stx_mask=0x17ff；由于 STATX_DIOALIGN=0x2000，本次返回不包含 DIO 对齐字段的有效标志，mem_align/offset_align 的零值不作语义解释。最终实现在当前环境中已报告页对齐 staging 的 9 MiB 完整读写及服务对照通过，证明本次参数组合下功能正常；目标文件的 DIO 数值约束及是否发生 buffered fallback 尚未核实。buffered 配置已有正常运行记录。

**结论：C 组可写“查询完成、当前参数功能验证通过”，不能写“已证明对齐约束或真实 DIO 路径”。**

依据：文件系统块大小 4096 并非通用 DIO 对齐查询接口；成功的 I/O 也不能独立排除允许的 buffered fallback。若要保留“实际绕过页缓存”或推广至其他部署的承诺，才需要补目标内核/文件/设备的有效约束依据或实际路径观测。可以携带这一明确限制提交 PR，不能将其隐藏为已经证明。[Linux open(2)](https://man7.org/linux/man-pages/man2/open.2.html)

### 2.2 第 72 行：TTFB 又被写成了首 token 时间

**结论：直接改为“首字节返回延迟（Time To First Byte）”。**

依据：curl 的 `time_starttransfer` 是从请求开始到收到第一个字节的时间；非 streaming 请求中，它不等于模型首个生成 token 的时间。原记录 2.74 秒和 2.32 秒可以保留，指标名称及解释须一致。[curl 官方接口说明](https://curl.se/libcurl/c/CURLINFO_STARTTRANSFER_TIME.html)

### 2.3 第 12 行：具体 GUP 因果链仍写得比证据更确定

**结论：保留 ACL 映射兼容性定位，将具体内核拒绝点改为“机制解释，现场未核实”。**

依据：第 64 行已列明 GUP 拒绝调用栈未取；背景段却把内核实际拒绝动作写成了定论。VmFlags 与缓冲类型对照支持该解释，但这不等于已观测到故障调用的具体分支。

建议替换根因句：

> 现场缓冲对照及 VmFlags 的 io/pf 记录支持 ACL host 特殊映射与当前请求 O_DIRECT 的 I/O 路径不兼容；普通 host staging 的恢复结果与该定位一致。具体 GUP 拒绝分支尚未现场核实。
