## 2. 具体怎么改

**结论：采用普通 host 内存的对齐中转区，并把它的整个生命周期放在同步 I/O 工作线程内；不能只把原缓冲替换为 `bytes()` 后直接交给 O_DIRECT。**

1. 写入：在调用方对源对象的预留仍有效时、提交线程任务前，取得 `bytes(buf)` 快照；工作线程新建对齐的普通 `mmap`，复制快照后执行写入。`bytes` 解决源数据所有权，`mmap` 解决实际 I/O 缓冲的地址对齐及特殊映射隔离。
2. 发布：临时文件使用 `O_TRUNC`，检查写入返回值必须等于请求长度；短写抛 `EIO`，进入已有失败清理，不能 rename 为正式缓存文件。
3. 读取：工作线程只读入自有对齐 `mmap`；完整读到期望长度才返回独立 `bytes`，随后释放 `mmap`。协程恢复后把完整数据复制到可写、连续的目标字节视图，最后设置命中位。
4. 取消：取消正在等待的协程不等于停止线程中的 I/O。线程继续操作自己的中转区；取消的协程不会再回写原目标，避免在这一适配器路径中晚写已被复用的目标。
5. 普通 buffered 分支不变，不增加配置项，不改 controller、vLLM 或 Ascend 插件。

对应代码已在仓库内；`candidate.patch` 包含生产文件和新增测试，`reference_rc7.diff` 仅用于追溯之前的参考方案。

**对齐条件：**实际使用 `O_DIRECT` 时，内存起始地址、I/O 长度和文件偏移必须满足目标文件所在栈的约束。当前补丁保留原有块大小假设，以 `lcm(PAGESIZE, statvfs.f_bsize)` 对齐地址；这不是通用 DIO 约束发现机制。部署到不同挂载/内核，或承诺普遍有效时，必须另行确认该倍数和长度/偏移条件足够。buffered 路径不需要为 O_DIRECT 做地址对齐。

## 4. 边界和风险

- 普通内存中转让内核不必直接向 ACL 特殊 host 映射做这一路文件 I/O；具体 GUP 拒绝分支未现场观测，不能写成内核级唯一根因。
- 写侧包含源到快照、快照到 mmap 的复制；读侧包含 mmap 到 bytes、bytes 到目标的复制。每个活动 worker 有额外约两份对象大小的暂存，且并发/排队快照会增加总量；性能与峰值 RSS 未实测。
- 本补丁验证的是适配器 I/O 缓冲所有权。完整 controller 预留协议、TTL、服务关闭终态，以及同 key 共用临时文件的并发竞态仍是独立议题，不能宣称全局 UAF 和全部关闭问题均已修复。
- 本机 Linux O_DIRECT 用例只检查带该标志的系统调用及读写结果，不证明实际绕过页缓存，也不替代 Ascend 验收。
