### 关键指标口径

- 外部KV命中率按LMCache查找命中的token数/输入token总数统计，外部缓存仅指P侧LMCache，不是D侧Mooncake传输命中率；完整4K命中按4096计，不是调度器扣除末token后的4095。另列命中请求比例。OFF写‘不启用’，证据不足写‘未核验’。分母为正式尝试，可能包含客户端最终失败请求。

- 平均prefill使用已关联到正式请求的P模型窗口（p_core_ms）：包含缓存恢复、调度推进和模型执行；不是纯NPU计算，不包含完整HTTP排队与P→D传输。n为可关联请求数；缺少这一观测的轮次写‘未采集’，不拿TTFT冒充。

- 平均decode是客户端首token返回到最后输出的平均耗时，按平均端到端耗时−平均TTFT计算；两者使用同一官方成功样本集合。它不是独立测量的D纯计算耗时，也不包含首token之前D的等待。当前未得到各轮统一的纯D计算均值。

- 三档分别展示，禁止混合不同输入长度或并发求一个总平均。各列延迟沿用官方自身成功分母，prefill与命中可能覆盖不同分母；同输入共同成功的因果比较仍见配对表。

| 指标 | 含义 |
|---|---|
| TTFT | 请求发出到收到首个有效输出的时间，越小越好；含排队、P处理、传D及首输出等端到端因素。 |
| TPOT | 首token后平均每个输出token耗时，越小越好；通常按（端到端耗时−TTFT）/（输出token数−1）计算。 |
| ITL | 流式相邻输出之间的时间间隔，越小越好；MTP可能一次返回多个token，不能将ITL直接等同TPOT。 |
| E2EL | 从发起请求到最后输出的端到端延迟，越小越好。 |
| P50 / P90 / P99 | 对应分位点；例如P90表示90%的统计样本不超过该值。小样本P99不等于稳定尾部上界。 |
| 标准差 | 结果离散程度，越大表示本轮波动越大；不代表统计显著性。 |
| 请求 / 输出 / 总token吞吐 | 分别为成功请求数、成功输出token、成功输入加输出token除以整档测试时长。请求吞吐单位请求/秒，其余token/秒。 |
| 成功率与耗时 | 成功率=成功数/正式尝试数；整档耗时包含等待与失败占用。预热不混入正式结果。 |
