# LMCache 六领域学习路线提纲：形成方案判断与指挥 AI 实现的能力

结论：按“基础概念 → 并发与系统地图 → 内存与 Tensor → 文件 I/O → 设备运行时 → 故障状态机 → LMCache 全链路”学习。最终应能解释问题、提出有依据的方案、限定 AI 的修改范围，并审查验证证据。

本提纲共 **66 个学习单元**：6 个基础桥接单元、六领域各 10 个单元。其中 **20 个标为 ★ 超重点，占 30.3%**。比例按单元数计算，不表示阅读量或学习耗时恰好占 30%。超重点也需要先读其前置单元。

## 一、如何使用与掌握标准

### 1. 三个深度

- **D1：认识职责。** 能用自己的话解释术语，知道它负责什么、与什么相邻。
- **D2：追踪流程。** 能在指定版本源码中找到入口、分支、调用者、资源持有者和错误出口。
- **D3：作出判断。** 能预测修改影响，提出至少一个替代方案，写清适用条件、代价及能推翻自己的实验。

单元末尾的“达标 / AI 任务”就是学习产出。无需以手写完整功能为考核；需要看懂关键代码、判断 AI 的实现是否符合接口和生命周期要求。

### 2. 本次案例的边界

- **硬件词汇前置：**CPU 是运行主机程序的处理器；RAM 是运行中的主机内存；GPU/NPU 是加速器；SSD 是存储设备。对象在 CPU 内存中，不表示其内容已经存在文件或设备内存中。本文的“设备”通常指加速器，不指 SSD。
- **问题背景：**现场曾报告某类 Ascend host 内存直接用于文件直接读写时失败，普通内存中转后恢复。这是问题线索；具体内核拒绝分支、所有历史错误是否同因，仍为**未核实**。
- **三类候选：**在文件 I/O 前中转；改变原生 host 内存的申请方式（#174 的方向）；撤销 lazy 分配器替换并恢复主仓能力（#305 固定候选）。方案覆盖不同入口，不是三个已经等价验证的修复。
- **请求挂死：**重启后第一个 load 请求挂死、后续请求正常，需要单独建立请求状态与数据路径证据。不能仅凭 allocator 修改，宣称它一定解决了挂死。
- **术语：**本题 L1/L2 是应用缓存层次；MP 是多进程模式；FS 是文件系统后端；host 指主机 CPU 一侧，device 指加速器一侧。
- **证据：**区分源码事实、官方接口说明、现场转述、推测、实测。未执行硬件验证的内容不能写成“已通过”。导师所说“aclrtMallocHost 头的问题”的含义仍未核实。

### 3. 源码版本

- 主仓公开阅读锚点固定为 `240506edf5146613b015e9e2e51189f1fc099b76`，不声明它是 2026-10-15 最新版本。

## 三、基础桥接：6 个单元

### P01｜字节、数量与单位〔D2〕

- **前置：**无。
- **学什么：**bit 是二进制位；byte 是字节，1 byte = 8 bit；KiB/MiB/GiB 按 1024 进位，KB/MB/GB 常按 1000 进位；十六进制常用于显示地址；取模 `%` 表示除法余数。
- **结合本题：**9 MiB = 9,437,184 字节；64 MiB = 67,108,864 字节。容量、元素个数、实际传输字节数要分开。
- **达标 / AI 任务：**能核对日志单位和 byte count；让 AI 同时报“元素数、每元素字节数、目标总字节数”，说明是否为连续布局。

### P02｜★ 地址、指针、引用与资源所有权〔D3〕

- **前置：**P01。
- **学什么：**地址是位置；指针是保存地址的值；引用是程序对对象的关联。owner 是负责资源存活和释放的一方，borrower 是借用者。保存了一个整数地址，不自动取得底层内存所有权。
- **结合本题：**Tensor、ctypes 对象、文件线程、NPU 任务可能关联同一块内存；它们不一定都有权释放它。
- **达标 / AI 任务：**画出“申请者—所有者—借用者—释放者”；要求 AI 明确底层 owner，而不是只说“变量还在”。

### P03｜★ 调用、分支、返回值与错误出口〔D3〕

- **前置：**P01。
- **学什么：**caller/callee 是调用者/被调用者；参数是输入，返回值是结果；if 决定路径；异常、错误码、False、返回字节数是不同失败表达。类、方法、接口只需先理解用途。
- **补充前置：**用户态是应用通常运行的执行域；内核态承担操作系统的受保护工作；syscall（系统调用）是应用请求内核执行操作的接口，例如 open/write。普通函数调用、进入内核、提交设备工作是不同边界。
- **结合本题：**`use_lazy` 决定入口；`pin_memory` 返回 False 可能只记录告警；`os.write` 返回的是字节数。
- **达标 / AI 任务：**为一段代码画成功、失败、清理三条分支；要求 AI 逐层说明错误有没有继续传到请求完成方。

### P04｜对象、可变性、复制与共享〔D2〕

- **前置：**P02、P03。
- **学什么：**对象身份与内容相等不同；mutable 是可修改，immutable 是内容不可原地修改；view 是观察已有数据的视图；copy 是得到独立数据。变量赋值不必然复制内容。
- **容易漏掉的条件：**`bytes(existing_bytes)` 可能直接返回原对象；不能把所有 `bytes(...)` 都说成“重新分配”。从可变缓冲取得内容快照与保证底层地址/对齐是两件事。
- **结合本题：**`bytes`、`bytearray`、`memoryview` 分别代表怎样的数据访问方式；`bytes` 内容不可变也不代表地址满足直接 I/O 对齐。
- **达标 / AI 任务：**预测修改原对象是否影响另一个对象；让 AI 标注每一步到底复制、包装还是借用。

### P05｜仓库、安装包、模块与运行版本〔D2〕

- **前置：**P03。
- **学什么：**repo 是源码仓库；commit 是固定版本；branch 是移动指针；PR 是提出修改的载体。Python import 加载模块；安装包路径与当前打开的仓库可能不同。`.so` 是 Linux 原生动态库。monkey patch 是运行时替换已有对象/方法。
- **结合本题：**文件改了、进程加载了、实际方法被替换了，是三件不同的事。
- **达标 / AI 任务：**要求 AI 给出 commit、Python 模块路径、实际函数来源和 native 库路径；不以“当前目录正确”代替运行版本证明。

### P06｜接口约定、正确性与证据〔D3〕

- **前置：**P02、P03、P04、P05。
- **学什么：**contract 是调用必须满足的条件及返回保证；invariant 是过程中必须保持的性质；功能正确、适用范围、性能收益是不同判断。观察到先后关系不等于证明因果。
- **结合本题：**“中转后成功”可能同时改变地址、来源、内容独立性和时序，不能只归因于其中一个。
- **达标 / AI 任务：**每个判断写“依据、未核实项、反例、验证方式”；要求 AI 先列接口条件再写改动。

## 四、领域一：LMCache 的业务与源码结构

**目标深度：**关键分配、存取与失败路径达到 D3；其他后端先到 D1。阅读锚点 S01—S08、S11。

### L01｜主仓、设备插件与两种运行形态〔D2〕

- **前置：**P03、P05。
- **学什么：**主仓负责通用缓存编排与设备抽象；Ascend 仓提供 NPU 实现和适配。embedded 是嵌入推理进程的运行方式，MP 是独立缓存服务参与的多进程方式；两者源码入口不同。
- **源码 / 本题：**辨认 `cache_engine.py → storage_backend/` 与 `integration/vllm/ → v1/multiprocess/ → distributed/`；这是职责地图，不是每次请求完全相同的调用栈。
- **达标 / AI 任务：**能判断截图来自哪种形态；让 AI 先确认运行形态，再选源码入口。

### L02｜KV Cache、chunk、key 与数据布局〔D2〕

- **前置：**P01、L01。
- **学什么：**token 是模型处理的序列单位；KV 是注意力机制中可复用的 Key/Value 状态；prefill 处理输入前缀，decode 逐步生成。chunk 是缓存分块；key 用于识别对象；shape/dtype/layout 分别是形状、元素类型、布局。
- **源码 / 本题：**理解正确 key 命中还需要正确版本、层、rank 和布局；字节数相同不保证模型语义相同。
- **达标 / AI 任务：**能说明“缓存了什么、为什么可复用、错一层/错一份分片会怎样”；要求 AI 区分字节正确和推理正确。

### L03｜★ 从配置追到实际执行入口〔D3〕

- **前置：**L01、P05、C08、T10。
- **学什么：**配置解析、默认值、校验与回退、工厂函数、插件激活。默认开启不等于最终仍开启；代码文件存在不等于被实际调用。
- **源码 / 本题：**读 `distributed/config.py`、`create_memory_allocator`、平台选择和 Ascend `__init__.py`；检查 `use_lazy`、传输模式、SHM、NUMA、hugepages 等相关分支。
- **达标 / AI 任务：**写出“配置→allocator 类型→真实函数→实际实现”；解释为何只跑 native `alloc_pinned_ptr` 探针不能验证 #305。

### L04｜★ MemoryObj 与共享缓存池的所有权〔D3〕

- **前置：**L02、L03、T01、T05、M08。
- **学什么：**MemoryObj 是缓存对象接口；metadata 描述数据；TensorMemoryObj 关联 Tensor；引用计数记录使用关系；pool 是大块内存，子对象可能只是其中的切片。
- **源码 / 本题：**读 `memory_management.py` 的对象、`byte_array`、`get_tensor`、ref count 与父分配器；关联 Tensor 的存储所有权和框架对象的逻辑引用。
- **达标 / AI 任务：**为一个对象画双层关系图：“逻辑对象是否还在用”和“底层 storage 是否还存活”；找出释放/复用边界。

### L05｜Lazy、Mixed、Tensor 分配器各自负责什么〔D3〕

- **前置：**L03、L04、T03、A02。
- **学什么：**池如何取得底层内存、如何划分给对象、怎样跟踪空闲空间；Lazy 是逐步开放/注册容量；Tensor 分配器可以管理现有 Tensor 的地址空间；Mixed 的入口需看配置。
- **源码 / 本题：**读三个 allocator 的构造、allocate/free/close；别把类名当成底层分配接口。NUMA、SHM 等路径要单独识别。
- **达标 / AI 任务：**画出 allocator 选择树；分别标明 #174 与 #305 覆盖的树枝。

### L06｜后台扩容、注册记录与容量日志〔D3〕

- **前置：**L05、A03、A04、A08、T09。
- **学什么：**最终 backing 容量、已开放容量、实际注册成功容量是不同量；后台线程按块处理；日志里的完成百分比取决于计数位置。
- **源码 / 本题：**读 lazy `__init__`、`_pin_memory_chunk`、`_expand_worker`、`_pin_record`；固定参考中后续扩容按 64 MiB 块，初始区间可能一次注册。
- **达标 / AI 任务：**解释为什么 100% 不一定表示全池成功注册；让 AI 返回容量、成功/失败次数和原始返回码。

### L07｜★ 保存与恢复两条完整链〔D3〕

- **前置：**L04、L06、F10、A06、C09。
- **学什么：**保存链 NPU KV→CPU 对象→L2 文件；恢复链 文件→CPU 对象→NPU KV。区分提交任务、实际 I/O、设备完成、对象可复用。
- **源码 / 本题：**沿 adapter、MP 服务、StorageManager、controller、L1、FSL2Adapter、设备传输画控制流和数据流；嵌入式路径另画，不拼成一条假调用链。
- **达标 / AI 任务：**在每个箭头标“进程/线程、输入输出、owner、完成信号、失败出口”；据此限定补丁落点。

### L08｜缓存状态、任务事件与请求完成〔D3〕

- **前置：**L07、C09。
- **学什么：**lookup 是查找，prefetch 是提前取回；命中、文件读成功、进入 L1、设备收到、请求结束是不同阶段。controller 用状态机管理在途任务。
- **源码 / 本题：**读 StoreController、PrefetchController 的状态与完成结果；从日志的计数更新位置理解“来源”和“当前所在层”，不靠日志名称猜测。
- **达标 / AI 任务：**解释哪一阶段失败会让调用方一直等；公共源码与照片格式不一致时注明 fork 差异未核实。

### L09｜修改边界与已有能力的复用〔D3〕

- **前置：**L03、L05、A07、F06。
- **学什么：**通用逻辑与设备实现的职责边界；改消费者、中间适配、生产者或撤销替换的不同代价；兼容版本与释放路径必须一起考虑。
- **源码 / 本题：**对比历史中转候选、#174 固定提交、#305 固定提交。#305 删除 lazy 替换，不等于修改 C++ 全局分配器。
- **达标 / AI 任务：**能写出“适用入口、未覆盖入口、额外复制、构建要求、版本条件、失败回退”的方案比较表。

### L10｜从方案判断变成 AI 任务与验收〔D3〕

- **前置：**L07、L08、L09、C10。
- **学什么：**将假设变成可实现的行为目标；列修改文件/函数、必须保持的条件、数据与资源正确性、测试判定；审查最终 diff 而非只听实现说明。
- **源码 / 本题：**按 E0 路径→E1 扩容/生命周期→E2 同缓冲文件与设备→E3 重启首 load 的顺序组织证据。
- **达标 / AI 任务：**写一页任务书；能拒绝“只测了另一条入口”“HTTP 200 就算成功”“取消后立即释放”等不充分交付。

## 五、领域二：PyTorch 的内存与执行架构

**目标深度：**Tensor、Storage、分配与传输完成条件达到 D3；Dispatcher、ATen、c10 先到 D1—D2。阅读锚点 S09、S10、D01—D04。

### T01｜★ Tensor、Storage 与实际数据地址〔D3〕

- **前置：**P01、P04、M01。
- **学什么：**Tensor 带 shape、dtype、stride（相邻元素如何移动）、device、storage_offset（相对存储的起始偏移）；Storage 承载底层数据；多个 Tensor 可共享 Storage。
- **源码 / 本题：**对照 `TensorImpl`、`StorageImpl` 与 LMCache TensorMemoryObj；区分逻辑元素字节数、实际存储跨度、Tensor 首地址与 Storage 首地址。
- **达标 / AI 任务：**能解释切片后对象变了而 backing 未换；让 AI 打印地址、偏移、布局及 owner，不只打印 Tensor 类型。

### T02｜视图、复制与连续布局〔D3〕

- **前置：**T01、P04。
- **学什么：**切片/view 可能共享数据；clone 创建独立副本；reshape 是否复制要看条件；contiguous 表示给定布局下的连续排列，不是文件 I/O 地址对齐。`contiguous()` 在已有连续布局时可能返回原对象。
- **源码 / 本题：**解释 `bytes`、memoryview、Tensor slice、clone 分别改变了哪些条件；连续数据不自动满足 O_DIRECT。
- **达标 / AI 任务：**对每步回答“共享吗、复制吗、布局变吗、地址变吗”；不能凭新变量名证明独立数据。

### T03｜★ torch.empty 到底申请了哪种内存〔D3〕

- **前置：**T01、M03。
- **学什么：**分别追 `device="cpu", pin_memory=False`、CPU pinned 以及 device Tensor。empty 的内容不能直接当有效数据，实验应主动填已知模式。
- **源码 / 本题：**#305 的普通 CPU backing 路线与 `empty(pin_memory=True)` 可能走设备 host allocator 的路线不同；`frombuffer` 则是在包装已有地址。
- **达标 / AI 任务：**先写清希望得到的存储性质，再让 AI 查参数和实际 allocator；禁止“函数名换了，所以来源换了”的推断。

### T04｜Allocator、DataPtr、缓存与释放回调〔D3〕

- **前置：**T03、P05、M03。
- **学什么：**Allocator 负责申请；DataPtr 关联指针、设备及 deleter（释放回调）；Storage 持有存储关系。caching allocator 可能将释放的内存留作复用，Python 对象消失不必然等于立即还给系统。
- **源码 / 本题：**看 `c10/core/Allocator.h`、`StorageImpl.h`；比较 torch 管理存储与 ctypes 包装 native 内存。
- **达标 / AI 任务：**指出应该配对的释放者；能想到地址复用可能暴露遗留注册，但不把这种可能直接写成已证实根因。

### T05｜buffer protocol、ctypes 与 frombuffer〔D3〕

- **前置：**P02、P04、T01。
- **学什么：**buffer protocol 让对象暴露原始数据区域；ctypes 可按地址描述 C 数据；frombuffer 创建共享已有缓冲的 Tensor。保住包装对象与保住底层分配，是需要分别检查的关系。
- **源码 / 本题：**读 `_allocate_cpu_memory`、native ptr→ctypes→Tensor 链；ctypes `from_address` 不接管原生内存的释放责任。
- **达标 / AI 任务：**能解释为什么“最后得到 Tensor”不能证明由 PyTorch 申请；要求 AI 明确真正存储 owner 与引用链。

### T06｜设备、copy/to 与两个传输方向〔D3〕

- **前置：**T02、C04、M08。
- **学什么：**H2D 是 host→device，D2H 是 device→host；`copy_` 写入已有目标，`to` 按参数转换设备/类型；CPU 数据可读与设备已写完不是一回事。
- **源码 / 本题：**追真实 worker transfer，而不是只写通用 Tensor copy；核对 bytes、dtype、shape、layout 与实际源/目标。
- **达标 / AI 任务：**分别验证两方向和完整往返；对推理张量按格式与容差判定，对原始字节按已知模式判定。

### T07｜★ stream、event 与真正完成的时间〔D3〕

- **前置：**T06、C03、M08。
- **学什么：**stream 是设备操作队列；event 是记录/等待执行进度的设备机制；synchronize 等待指定范围完成。host 函数返回、入队、设备完成是不同时间点；不同 stream 的依赖不能只靠代码前后顺序猜测。
- **源码 / 本题：**为“NPU 写 CPU→文件读 CPU→释放 CPU”画时间线；CUDA 文档帮助理解机制，但不能直接把实现保证套给 NPU。
- **达标 / AI 任务：**给每次读、写、复用和释放指定完成依据；禁止用“sleep 一会儿”代替正确依赖。

### T08｜Python、ATen、c10、Dispatcher 与 native 扩展〔D2〕

- **前置：**P05、T01、T04。
- **学什么：**ATen 是张量操作相关实现层；c10 提供 Tensor/Storage/Allocator 等基础设施；Dispatcher 根据设备等信息选实现。pybind/ctypes 是 Python 接入原生代码的方式；API 是接口，ABI 是二进制调用约定。
- **源码 / 本题：**区分 Tensor 的存储结构与“Python API→调度/原生入口→CPU/CUDA/NPU 实现”的执行路线，它们不是同一张图。
- **达标 / AI 任务：**知道该追 allocator、设备接口还是算子，不要求实现 Dispatcher；让 AI 给出实际后端证据。

### T09｜pinned、注册与框架观测的边界〔D3〕

- **前置：**T06、T07、T04。
- **学什么：**框架 pinned 分配、对外部地址注册、CPU 锁页是有关联但不同的机制；具体保证由接口与版本决定。`non_blocking=True` 是请求一种执行方式，不是独立证明实际异步。
- **源码 / 本题：**区分 torch_npu host allocator 记录与 LMCache NPU backend 的注册表；`is_pinned` 等观察是否涵盖外部注册需核对具体实现。
- **达标 / AI 任务：**以注册返回值、实际设备完成及受控测量分别证明能力、正确性与性能，不能用一个布尔量替代三者。

### T10｜实际加载的 Python、扩展库与版本一致性〔D3〕

- **前置：**P05、T08。
- **学什么：**解释器、环境、import 路径、已构建 `.so`、共享库搜索路径可能分别指向不同版本；源码改动与重启新进程、原生重编译的要求不同。
- **源码 / 本题：**#305 是 Python 删除改动；#174 涉及 C++。两者验证加载方式不同，不能只看 `pip show`。
- **达标 / AI 任务：**让 AI 同时记录 Python 模块、类方法来源、native 库路径和源码基线；不为核对版本而升级依赖。

## 六、领域三：操作系统内存管理

**目标深度：**地址、页、映射、所有权达到 D3；内核 GUP 路径先到 D1—D2，有证据指向时再深入。资料 D05—D09。

### M01｜进程地址空间、虚拟地址与物理页〔D2〕

- **前置：**P02、C02。
- **学什么：**每个进程有自己的虚拟地址空间；页表建立虚拟地址到实际页面的映射；同一个数值地址在两个进程里不代表同一块内存。
- **结合本题：**跨进程应传共享区域身份与偏移或协议定义的句柄，而不能随意传一个裸指针当作通用地址。
- **达标 / AI 任务：**能把“哪个进程的地址”写进证据表，解释为什么单进程探针不能自动证明 MP。

### M02｜★ 页、对齐与范围计算〔D3〕

- **前置：**P01、M01。
- **学什么：**page 是系统管理内存的粒度；alignment 是地址满足指定边界；向下对齐基址、向上扩大覆盖长度。页大小、文件 I/O 对齐和设备接口对齐可能不同。
- **结合本题：**检查 `ptr % alignment`；扩大注册范围只改变注册参数，不会改变文件收到的原始指针。
- **达标 / AI 任务：**给定 ptr/size/page 能算完整覆盖区间；能发现块间页重叠的可能并查接口要求，不能假定页永远是 4096。

### M03｜malloc、mmap 与分配释放配对〔D3〕

- **前置：**M01、M02。
- **学什么：**malloc 是用户态分配接口；mmap 建立映射，匿名映射不以普通文件作为数据来源；free 与 munmap 对应不同释放机制。PyTorch/native allocator 还可再包一层管理。
- **补充前置：**`MAP_SHARED` 用于共享映射；`MAP_PRIVATE` 的私有写入采用写时复制（COW，即写入时形成私有页面）。用了 mmap 不等于已建立所需的进程间共享关系。
- **结合本题：**普通 Tensor、mmap、ACL 分配不能混用释放函数；为了对齐多申请后切片，要保存真实 backing 及释放所需信息。
- **达标 / AI 任务：**为候选方案写资源配对表；让 AI 同时实现成功和中途失败的清理。

### M04｜虚拟容量、缺页与实际驻留〔D2〕

- **前置：**M01、M03。
- **学什么：**建立地址范围、实际触碰页面、页面驻留在 RAM 中是不同状态；page fault 是需要内核处理的页面访问事件；RSS 是进程驻留内存的观测之一。
- **结合本题：**lazy 池可能先建立最终大小的 backing，再逐步注册/开放容量；不能把“lazy”理解成每次才新建一个小 Tensor。
- **达标 / AI 任务：**解释 final size、available size、RSS 和注册容量为何不必相同；避免用一个计数推断所有状态。

### M05｜★ 锁页、设备注册与映射各自保证什么〔D3〕

- **前置：**M02、M03。
- **学什么：**mlock 提供操作系统页面驻留相关保证；设备注册让驱动按接口管理外部区域；设备映射建立设备可用的地址关系。一个接口可能内部完成多项工作，但不能从名字推断全部保证。
- **结合本题：**额外 mlock 不自动等于完成设备注册；注册成功也不自动证明文件直接 I/O 兼容。munmap 会解除其范围内相关内存锁。
- **达标 / AI 任务：**分别列“CPU 可访问、驻留、设备可用、文件可用”的证据；不要用单一成功返回替代整张表。

### M06｜VMA、VmFlags 与内核获取用户页〔D2〕

- **前置：**M02、M03、F04。
- **学什么：**VMA 是进程一段虚拟映射的描述；VmFlags 是映射属性标记；GUP（get_user_pages 等机制）是内核获取/固定用户页的一组相关路径。I/O 映射、PFN 映射等属性可能影响内核处理方式。
- **结合本题：**`io`/`pf` 等是排查线索，不能单凭它们宣布某内核分支已经拒绝。需要内核版本、调用路径及错误证据。
- **达标 / AI 任务：**区分“映射不同”和“已证明具体失败机制”；缺栈或跟踪证据时明确未核实。

### M07｜NUMA、位置与性能〔D2〕

- **前置：**M01、C02。
- **学什么：**NUMA 将处理器与内存划成有距离差异的节点；绑定策略影响页面位置；CPU 核、NUMA 节点、设备编号是不同标识。
- **结合本题：**NUMA 分配可能走另一条 mmap/注册路线；普通分配修复不能自动覆盖它。位置变化也可能改变性能对照条件。
- **达标 / AI 任务：**能分开“正确性路线”和“位置优化”；让 AI 保留原绑定并说明是否进入不同 allocator。

### M08｜★ UAF、复用与异步资源生命周期〔D3〕

- **前置：**M03、P04、C04。
- **学什么：**UAF（use-after-free）是释放后仍使用；逻辑释放回池后被复用也可能破坏旧任务的数据。存储仍存在与内容未被他人修改是不同保证。
- **结合本题：**线程池或设备操作还在读，调用方就释放/复用缓存对象，会造成时序错误；复制可能缓解它，也同时改变其他因素。
- **达标 / AI 任务：**画存活和可修改时间线；要求每个在途任务有明确持有关系与完成后释放责任。

### M09｜内存额度、锁页额度与错误归类〔D2〕

- **前置：**M04、M05、C02。
- **学什么：**RAM、容器/cgroup 限制、进程锁页限制和驱动注册额度是不同资源；OOM 是内存耗尽相关故障，不是所有申请失败的总称。
- **结合本题：**大池测试失败不必然表示方案机制错误；泄漏、额度不足、上下文缺失、参数不符要分开。错误码含义按实际版本查证。
- **达标 / AI 任务：**让 AI 保留大小、已用量、原始错误码和调用点；不以耗尽主机额度作为日常验收。

### M10｜观测内存：地址、映射与计数〔D3〕

- **前置：**M02、M04、M06、M09。
- **学什么：**围绕具体 ptr 看对应 `/proc/<pid>/maps`、`smaps` 与范围；核对页大小、地址余数、实际 RSS/锁页等计数；知道不同驱动机制未必都体现在同一个计数里。
- **结合本题：**只读取目标映射，保存原始数值；不能把 `VmLck=0` 或一次地址变化当成全部内存性质的结论。
- **达标 / AI 任务：**形成小证据表，而不是全系统日志堆积；每个观测项写明它能证明什么、不能证明什么。

## 七、领域四：文件系统与 I/O 正确性

**目标深度：**调用返回、对齐、缓冲、发布语义达到 D3；文件系统内部实现先到 D1。源码 S07，资料 D10—D15。

### F01｜文件描述符、打开标志与文件偏移〔D2〕

- **前置：**P03、M01。
- **学什么：**fd 是进程用于访问打开文件的句柄；open 的标志控制创建、读写、截断等行为；offset 是当前读写位置；read/write 与显式指定偏移的接口要区分。
- **源码 / 本题：**看 FS adapter 的 open、seek、read/write、close；线程共享同一打开文件对象时，偏移变化也可能形成竞争。
- **达标 / AI 任务：**能说明一次调用实际操作的文件、位置、长度和标志；让 AI 提供这些参数，而非只贴文件名。

### F02｜★ 短读、短写、EOF 与返回字节数〔D3〕

- **前置：**F01、P01。
- **学什么：**请求 100 字节而返回 60，就是本次只完成 60；EOF 是文件结束；异常和不足量是不同结果。成功调用不等于全部传输。
- **源码 / 本题：**读 baseline FS helper 的 read/write 处理，设计短写注入。O_DIRECT 的后续重试还需重新满足地址、长度和偏移约束，不能照搬普通缓冲 I/O 的剩余量循环。
- **达标 / AI 任务：**列完整、短量、零量、异常四种分支；要求未完成对象不能被当成完整缓存发布。

### F03｜页缓存与普通文件读写〔D2〕

- **前置：**F01、M01。
- **学什么：**page cache 是内核用于缓存文件内容的内存；普通 write 返回后数据可先处于内核缓存，再由回写落到存储。应用 L1 和内核页缓存是不同层。
- **源码 / 本题：**区分应用 L1 冷、内核文件页缓存冷、磁盘文件不存在；重启服务不自动使后两者成立。
- **达标 / AI 任务：**在测试描述中分别标注三种状态；不能用“重启过”证明实际从 SSD 读取或严格绕过页缓存。

### F04｜★ O_DIRECT 的实际地址、长度和偏移条件〔D3〕

- **前置：**F02、F03、M02、T02。
- **学什么：**O_DIRECT 请求一条尽量减少页缓存影响的文件路径；限制依赖文件系统、内核和接口。核对实际传入指针，不只检查 allocation base 或池内 offset。
- **源码 / 本题：**读取目标挂载支持的 `statx` 对齐字段并确认有效标志；没有查询能力时记录未知，不能把 4096、512 或 CPU 默认对齐当普遍规则。
- **达标 / AI 任务：**给出地址/长度/偏移要求、原始值与余数；说明何时可用直接 I/O、何时应拒绝或按既定策略处理。

### F05｜完成、可见、原子性与持久化〔D3〕

- **前置：**F01、F02、F03。
- **学什么：**I/O 完成、其他读取者可见、操作原子生效、故障后仍保留是不同性质；fsync 与目录同步解决持久化的特定部分；O_DIRECT 本身不是 fsync 的同义词。
- **源码 / 本题：**明确缓存是否只需重启服务复用，还是要求断电恢复；不能因学习持久化就无条件增加所有 fsync。
- **达标 / AI 任务：**先写产品要求，再选择同步/发布策略；“读回一致”和“断电持久”分开验收。

### F06｜★ 临时缓冲与多变量对照〔D3〕

- **前置：**F04、T02、T05、P06。
- **学什么：**staging 是为交接而使用的中间缓冲；复制可能改变来源、地址、可变性和时间。所有权独立、地址对齐、设备兼容是不同属性。
- **源码 / 本题：**解释历史 bytes/mmap 中转为什么有定位价值，却不能单独证明 UAF、对齐或 ACL 映射中的某一个。
- **达标 / AI 任务：**要求对照分别控制 owner 存活、实际对齐和分配/注册方式；每次记录改变了哪些变量、哪些仍未区分。

### F07｜临时文件、截断、rename 与并发发布〔D3〕

- **前置：**F01、F02、F05。
- **学什么：**truncate 改变文件长度；旧长文件若只覆写前半，可能留尾部；先写临时文件再 rename 可用于发布完整对象。rename 的原子可见性有条件，不自动包含断电持久化或跨文件系统移动。
- **源码 / 本题：**检查中途失败是否留下临时文件、旧对象是否仍可读；重试是否覆盖另一代结果。
- **达标 / AI 任务：**画“创建→写全→按需求同步→发布→失败清理”；实际修改只针对已确认需要，不把学习内容全塞进补丁。

### F08｜文件映射、共享内存、DAX 与直接 I/O 的区别〔D2〕

- **前置：**F01、F03、M03、C07。
- **学什么：**mmap 是建立地址映射；SHM 是进程间共享区域；文件 mmap 与匿名 mmap 不同；DAX 是特定存储/文件系统的直接访问机制；RDMA 是网络适配器参与的远程内存访问机制。它们不因都有“直接”就等价。
- **源码 / 本题：**识别哪些 allocator/adapter 是另一路线，避免把它们强行纳入 #305 结论。此阶段只认识边界。
- **达标 / AI 任务：**看到相似术语能先查数据流、映射与 owner，不复制另一后端的释放方式。

### F09｜挂载、文件系统支持与可移植性边界〔D2〕

- **前置：**F04、F05。
- **学什么：**路径落在哪个 mount、文件系统类型与选项、是否容器绑定或网络存储，会影响可用能力；内核/API 返回条件比目录名更可靠。
- **源码 / 本题：**相同 `/mnt/...` 名字不证明是同一种 SSD 或文件系统；Windows 普通文件实验不能替代黄区 Linux 的 O_DIRECT 验收。
- **达标 / AI 任务：**让 AI 保留挂载与内核条件，区分接口功能验证、严格路径验证和性能测量。

### F10｜文件故障分类与最小验证矩阵〔D3〕

- **前置：**F02、F04、F07、P06。
- **学什么：**参数不符、短量、文件缺失、权限、空间不足、设备错误、竞争和旧数据分别建假设；对数据读写应有已知模式、独立预制读控制和完整比较。
- **源码 / 本题：**一次写失败不能让读实验完全失去判断；HTTP 成功不能证明文件对象完整；对齐、所有权、映射来源需要分组对照。
- **达标 / AI 任务：**写出每组输入、唯一变化、预期结果、实际数值与结论边界；不要求无目的的全文件系统兼容矩阵。

## 八、领域五：Ascend 运行时、注册与设备传输

**目标深度：**host 内存路线、线程上下文、传输与清理达到 D3；驱动内部和设备 kernel 编写先到 D1。源码 S08、S10—S13。

### A01｜torch_npu、CANN、驱动与设备的分工〔D2〕

- **前置：**T08、T10、L01。
- **学什么：**torch_npu 提供 PyTorch 的 NPU 后端；CANN 提供相关设备软件栈与运行时能力；驱动承担更低层设备交互；AscendCL/ACL 是其中可调用的一组接口。SDK 是开发工具/库集合。
- **源码 / 本题：**LMCache 的平台层、Ascend 插件、PyTorch 后端和运行时不是一个分配器；每层都可能包装或替换行为。
- **达标 / AI 任务：**画 Python→插件/扩展→运行时→驱动→设备路线；发生错误时保留实际发出错误的层。

### A02｜★ 运行时申请与普通内存注册两条路线〔D3〕

- **前置：**T03、T04、M05、A01。
- **学什么：**一条路线由 `aclrtMallocHost` 申请并配套释放；另一条先有普通 host 存储，再按目标版本接口注册/解绑。注册不会把存储所有权自动转给 ACL。
- **源码 / 本题：**读 `csrc/mem_alloc.cpp`、主仓 NpuPinMemoryBackend 与 lazy 分配器；这是能够想到 #174/#305 思路的核心知识。
- **达标 / AI 任务：**先核实版本支持、参数和消费者要求，再让 AI 比较方案；PyTorch 的 backing 不能交给 `aclrtFreeHost` 释放。

### A03｜注册范围、记录键与块边界〔D3〕

- **前置：**A02、M02。
- **学什么：**原调用 ptr、按页对齐的注册 base、扩大后的 size 可能不同；成功注册必须记下可用于撤销的信息；跨块范围若重叠，须查接口是否允许。
- **源码 / 本题：**读 NPU backend 的 round_down/round_up 和 registered_bases；主仓扩大注册范围并不修正 Tensor 的 I/O 首地址。
- **达标 / AI 任务：**手算一个非页对齐例子，明确注册和解绑分别传什么；要求记录表只在成功后更新并正确处理失败。

### A04｜★ 线程上下文与设备选择〔D3〕

- **前置：**C02、A01、T07。
- **学什么：**context 是运行时执行环境；某些状态按线程保存，主线程初始化不保证新线程拥有相同当前上下文。设备编号、rank、线程身份需分开。
- **源码 / 本题：**看 NpuPinMemoryBackend `_ensure_context`；为什么真实后台扩容线程比主线程模拟循环更有验证价值。
- **达标 / AI 任务：**要求在实际调用线程确认上下文和设备，不硬编码所有 rank 使用设备 0；错误含义按版本核对。

### A05｜host pointer、device pointer 与映射能力〔D3〕

- **前置：**A02、A03、P02。
- **学什么：**host pointer 是 CPU 一侧地址；device-mapped pointer 是设备可使用的映射地址/别名；地址是否相同以及哪个接口接收哪个地址，取决于具体能力与合同。DMA 指设备参与数据搬运的机制。
- **源码 / 本题：**比较 register_ptr 的返回结果、get_device_ptr 类入口与普通 copy API；不要假定所有设备 kernel 接受同一个 host 数值。
- **达标 / AI 任务：**画两个地址与同一存储的关系；让 AI 解释真实消费者怎样取得正确地址。

### A06｜通用复制、native 传输与真实 MP〔D3〕

- **前置：**A05、T06、T07。
- **学什么：**通用 copy API 可能包含内部适配；native kernel 是原生设备执行实现；真实 MP 还包含协议、布局和多进程交接。一个较低层实验不覆盖全部上层路径。
- **源码 / 本题：**把真实 worker/server transfer 与普通 copy 往返分别测；“同缓冲文件→设备”必须保留源头证据。
- **达标 / AI 任务：**明确每个实验验证到哪一层；通用传输通过后，仍按实际 TP/布局验证真实消费者。

### A07｜Python 绑定、native 实现与运行时替换〔D2〕

- **前置：**A01、A02、T10。
- **学什么：**pybind 导出 C++ 函数，ctypes 调共享库；facade 是上层统一入口；monkey patch 是替换运行对象。函数名相同不保证绑定目标相同。
- **源码 / 本题：**追 NpuDeviceOps→Ascend ops/c_ops→C++；再看 Ascend `__init__.py` 如何改主仓行为。
- **达标 / AI 任务：**说明改 Python、C++ 或主仓接口分别需要什么交付；新进程验证加载，避免只改未使用的源码。

### A08｜★ 配套清理、失败回滚与重复生命周期〔D3〕

- **前置：**A02、A03、A04、M08、T07。
- **学什么：**先完成设备使用，再解除成功的注册，再由真正 owner 释放；部分成功后失败也要有明确回滚；重复关闭与失败重试应按实际合同处理。
- **源码 / 本题：**主仓 lazy close 调用解绑但未检查其返回值；“close 没异常”不能证明没有泄漏。反过来，不能为保清理把仍在使用的地址强行释放。
- **达标 / AI 任务：**给出资源获取/释放表和返回值；同进程少量创建—关闭检查即可，失败后停止制造更多泄漏。

### A09｜版本能力、错误码与同步回退〔D3〕

- **前置：**A01、A02、M09、P06。
- **学什么：**区分接口不可用、参数错误、上下文缺失、资源不足与未知设备错误；fallback 是失败后选择的替代路径。某路径回退后功能正常，不证明原能力正常或性能保持。
- **源码 / 本题：**`507899` 等数字应保留原文并查实际版本；作者一个环境中的解释不自动覆盖全部历史实例。
- **达标 / AI 任务：**要求 AI 标出成功路线、回退路线和未知项；不默认靠升级解决，也不把未崩溃当完整通过。

### A10｜为什么 GPU 与 NPU 可能表现不同〔D3〕

- **前置：**A02、A06、A09。
- **学什么：**差异可能来自 allocator、映射属性、驱动、注册接口、同步和 kernel 的地址要求；“都叫 host 内存”不代表同一实现。比较的是具体软件路径和版本。
- **源码 / 本题：**比较 CUDA 分配/注册与 Ascend 对应入口，再看文件 I/O 的实际缓冲；不归纳为所有 GPU 都正确、所有 NPU 都失败。
- **达标 / AI 任务：**能提出软件层面的条件化解释；要求对照保持内容、对齐和生命周期一致，并明确仍未核实的机制。

## 九、领域六：并发、分布式与资源生命周期

**目标深度：**进程/线程、取消、等待关系和请求状态达到 D3；分布式算法先学足以判断本题的范围。资料 D16—D19，源码 S01、S02、S06、S08。

### C01｜并发、并行、同步与异步：两组不同维度〔D2〕

- **前置：**P03。
- **学什么：**并发是多项工作交错推进；并行是同一时刻实际执行多项工作。同步/异步关注调用与结果交付方式；阻塞/非阻塞关注调用者是否被阻住。它们不能互相替代。
- **结合本题：**单线程事件循环也能并发等待多个文件任务；多个 stream 有并行机会，不等于每次一定并行；后台线程内部仍可调用同步 I/O。
- **达标 / AI 任务：**用时间线而非名词猜性能；要求 AI 指出实际执行者和等待点。

### C02｜★ 进程、线程与线程局部状态〔D3〕

- **前置：**P02、C01。
- **学什么：**进程通常有独立地址空间；线程共享同一进程中的堆等资源，但有各自栈和线程局部状态（TLS）。PID/TID 分别标识进程/线程；共享并不自动保证访问安全。
- **结合本题：**扩容线程、文件线程池、推理进程、缓存服务进程要分开画；设备当前上下文可能是线程局部状态。
- **达标 / AI 任务：**为每个动作标 PID、线程、设备；不能用主线程成功替代后台线程验证，也不能把裸 ptr 跨进程直接使用。

### C03｜竞态、锁、事件、条件变量与 GIL〔D2〕

- **前置：**C02。
- **学什么：**race 是结果受执行交错影响；锁保护互斥访问；事件表达某条件；条件变量用于等待并重新检查条件。常规 CPython 的 GIL 是解释器机制，不能替代业务锁，也不排除 native/I/O/设备并发。
- **结合本题：**检查 pin 记录、空闲池、close 与后台扩容是否竞争；event 被 set 表示什么要看业务定义。
- **达标 / AI 任务：**指出共享状态和保护方式；让 AI 解释锁保护的具体不变量，而不泛泛“加锁确保安全”。

### C04｜协程、事件循环、Task、Future 与线程池〔D2〕

- **前置：**C01、C02、P03。
- **学什么：**协程可在等待点让出执行；事件循环调度任务；Task 管理协程运行；Future 表示尚待交付的结果；executor/线程池负责实际执行工作。`await` 不代表新建线程。
- **结合本题：**`run_in_executor` 把同步 I/O 交给线程；asyncio 一层的 Task 与线程层的 Future 不应混称一个可硬中断的任务。
- **达标 / AI 任务：**画出协程→线程→系统调用→完成回传；明确谁仍持有缓冲，异常怎样传回。

### C05｜★ 超时、取消等待与底层任务停止〔D3〕

- **前置：**C04、M08、T07。
- **学什么：**timeout 是等待超限；cancel 是按对象合同请求取消。`concurrent.futures.Future` 已运行时不能靠 cancel 强停；asyncio Task 有不同的协作式取消机制，不能混用两者结论。
- **结合本题：**上层协程不再等待，不证明线程 syscall 或 NPU 已停止。请求失败后，缓冲仍可能需要存活到真正完成。
- **达标 / AI 任务：**分别记录“取消提出、等待结束、底层完成、释放”；要求 AI 给清理责任，不把 cancel 返回当安全释放证明。

### C06｜死锁、饥饿与缺失完成通知〔D3〕

- **前置：**C03、C04、C05。
- **学什么：**deadlock 是形成无法推进的等待；starvation 是任务长期拿不到资源；线程池满、持锁等待、事件永不触发、某参与者缺席都可能表现为挂住。
- **结合本题：**首 load 挂死需要等待图：谁在等哪个 Future/event，谁本应触发，在哪个失败分支未触发。增加 timeout 只改变等待上限，不自动解决源头。
- **达标 / AI 任务：**提出能定位等待点的最小日志或栈采集；不一开始改所有 timeout 或大范围加锁。

### C07｜IPC、消息、序列化与共享内存〔D2〕

- **前置：**C02、P04。
- **学什么：**IPC 是进程间通信；消息传身份、命令或结果；serialization 是把对象编码以便传输；SHM 让进程映射同一区域。控制平面安排工作，数据平面搬运内容。
- **补充分布式词汇：**RPC 是通过通信请求另一执行者完成操作，可发生在同机或跨机；endpoint 是通信终点，常由地址/端口标识；socket 是常见通信接口。数据发出、对端处理和应答收到，是三个不同事件。
- **结合本题：**缓存 key/偏移/任务 ID 可以经消息传，KV 数据可能走复制或共享区域；共享区域在各进程中的虚拟基址不必相同。
- **达标 / AI 任务：**分开画命令箭头与数据箭头；检查映射、同步、close 和 unlink 的角色。

### C08｜分布式基础：主机、rank、进程组与模型并行〔D2〕

- **前置：**C07、L02。
- **学什么：**分布式系统由多个执行者通过通信协作，可在一台或多台机器；rank 是某进程组内编号，world_size 是该组参与进程数。local rank 是本机局部编号，不能直接当设备身份的普遍保证。
- **结合本题：**TP 切分张量/模型计算；PP 按模型阶段分工；DP 让不同副本处理数据。它们是并行策略，多进程是执行组织方式，两者不等同。collective（集合通信）要求相关成员按约定参与，NCCL/HCCL 是相应平台常见通信库。
- **补充前置：**process group 是参与某次协作的一组进程，不一定等于全部进程；barrier 是等待组员到达的同步点。缺少成员或通信调用顺序不符可能造成等待，不能因此直接推断为文件 I/O 卡住。
- **达标 / AI 任务：**画主机—进程—设备—并行组映射；知道单机多进程不等于多机，某个 rank 成功不证明其他分片已经就绪。

### C09｜★ 请求状态机、部分失败、重试与幂等〔D3〕

- **前置：**C05、C06、C08、F07、T07。
- **学什么：**状态机用状态和事件描述推进；跨进程可能出现“对方已完成，但回复丢失/超时”，调用方只能知道结果未知。retry 是再尝试；幂等是重复执行的预期效果等同一次，需结合请求身份与实际操作判断。
- **补充前置：**request ID 标识请求；generation/epoch 可用于区分对象或进程的不同代次。它们是否已在项目使用要读协议，不因学习这些词就要求新增整套机制。网络可靠传输也不自动赋予应用“恰好执行一次”的效果。
- **结合本题：**区分提交、执行、文件完成、设备完成、上层通知、失败收尾；重试可能重复注册或发布。重启后的新 L1 与旧 L2，还涉及启动发现和首次使用状态。
- **达标 / AI 任务：**画成功与每处失败的终态；明确哪个进程负责通知、何时重试安全；不把 HTTP 或 rank 0 返回代替全链完成。

### C10｜观测、因果实验与证据分层〔D3〕

- **前置：**C09、P06、F10、A08。
- **学什么：**trace 关联同一次请求的事件；统一记录请求 ID、进程/线程、rank、时间与资源身份；A/B 保持基线和输入，B 只改变目标行为。跨机器时间戳直接相减还需考虑时钟条件。
- **结合本题：**先确认代码加载，再确认路径，再测功能与生命周期，最后才谈性能；A 无法复现而 B 通过，只能说明候选功能通过，修复因果未核实。
- **达标 / AI 任务：**能审查“证据是否来自目标入口、同缓冲、真实 MP”；为每条结论注明已证实、推测、未核实。

## 十一、把知识变成方案判断：4 次综合练习

### 练习 1：三种改法的覆盖和代价

- **前置：**阶段 0—6。
- **任务：**比较文件中转、#174 原生分配路线、#305 恢复 lazy 主仓实现；不要先看结论，自己写优缺点。
- **必须比较：**实际覆盖入口、普通/NPU 可用条件、额外复制与容量成本、地址对齐、owner、设备完成、清理、版本条件、构建与加载证明。
- **过关：**解释何时一个方案适用、何时另一个更局部；不写“所有 NPU 必须如此”或“Tensor 一定普通内存”。

### 练习 2：区分 UAF、对齐与内存来源兼容

- **任务：**为三个假设设计最少的有区分力实验。先画自变量/保持条件表，再让 AI 实现探针。
- **要求：**UAF 对照保持来源与对齐并确保 owner/最后使用时序；对齐对照保持来源与生命周期；来源对照保持实际对齐、内容和生命周期，并记录注册状态。
- **过关：**认识注册本身也可能改变映射属性，必要时增加同一普通 backing 的注册前/后对照；无法一次只改一项时，明确实验的区分上限。多个机制也可能同时存在。

### 练习 3：首请求挂死的状态与等待图

- **任务：**以旧 L2、新 L1、重启后首 load 为输入，标出 startup discovery、lookup、读文件、设备传输、完成通知各节点；这些英文分别指启动发现、查找与处理阶段。
- **要求：**先确认请求真的命中目标 L2；列出每节点“谁等待、谁触发、失败后谁收尾”；比较首请求与第二请求，不把二者混成一次成功。
- **过关：**能解释 allocator 可能避免某个失败触发，却不直接修复所有请求状态机错误；给出最小日志/栈和判断表。

### 练习 4：审查 AI 的实现与实验报告

- **任务：**让 AI 提交小 diff、源码路径证据、正反例、原始数值与结论；自己按 contract 和资源图审查。
- **常见不充分证据：**只测试 native 入口却声称 lazy 已修复；pool 100% 却没看注册失败；close 无异常却没看解绑；通用 copy 通过却没测真实 MP；HTTP 200 却没证明 L2 恢复。
- **过关：**指出具体缺哪条证据，不以“再跑全量测试”替代针对性核对；AI 可以提出方案，但选择依据必须能由你复述。

## 十二、指挥 AI 的任务书：每次固定写这 8 项

1. **现象与目标：**在哪个版本/配置出现什么；希望用户可见行为变成什么。
2. **假设与反证：**怀疑哪层，已有支持，哪些未知，何种结果会推翻假设。
3. **实际路径：**从配置到具体函数/原生实现，哪些入口不在范围内。
4. **接口条件：**输入布局、地址/长度、注册、线程上下文、返回值与错误传播。
5. **资源与时序：**申请者、owner、借用者、最后完成者、解除注册和释放责任。
6. **修改边界：**允许改的文件/函数、保持的版本与配置、不引入额外中转或改模式来掩盖问题。
7. **验收判定：**正反对照、要回传的具体数值、真实 MP 和首请求是否需要验证。
8. **交付结论：**diff 与原始结果；功能、覆盖、清理和性能分开，未核实明确列出。

**本题示例提纲：**

> 判断现场是否存在被 Ascend 替换的 lazy L1 池；若存在且主仓能力满足，隔离应用 #305 固定删除改动。保持主仓、设备、挂载和传输模式。分别证明候选已加载、真实分配路径切换、注册/解绑成功、同缓冲文件/设备链正确，以及重启首个 L2 load 完成。若原方案未复现故障，只报告候选功能通过。不要把另一条入口的结果或旧中转带来的成功作为修复证据。

## 十四、前置知识自检与学习边界

结论：以本文阶段表为学习顺序，以单元前置为具体依赖。任何“能写实现”的要求都应先落到“能解释、能预测、能列验收条件”。

- 先学 P02/C02，再学地址空间、shared memory 和线程 context。
- 先学页与范围计算，再学 O_DIRECT 和 host register。
- 先学 Tensor/Storage 与 buffer owner，再讨论 bytes/frombuffer/切片等候选。
- 先学 Task/Future/线程执行者，再讨论取消、UAF 和 close。
- 先学 rank、进程组和分片，再谈真实 TP/MP 验收。
- 先学失败状态与完成通知，再判断首 load 挂死；未定位等待关系时不宣布根因。
- 深度学习数学、训练自动求导、编译器优化、全套网络协议、共识算法与驱动开发，本阶段只了解相关用途；有具体问题再展开。
- 需要真实设备的结论交给黄区执行，文本回传即可；本地概念练习和静态源码阅读不替代硬件验收。

### 1. 自检后补入的前置

- 补入 CPU、RAM、加速器与 SSD 的角色，避免把三种数据位置混成一个“内存”。
- 补入用户态/内核态/系统调用，说明为什么 CPU 读得了不等于另一接口的要求已满足。
- 补入 bytes 转换的例外、mmap 共享/私有与写时复制，避免错误推广。
- 补入 RPC、endpoint、socket、进程组和 barrier，串起 MP 与分布式词汇。
- 补入请求身份、代次和“结果未知”，解释为什么超时后不能无条件重试或释放。
- 已核对 66 个单元均出现在阶段安排中，前置顺序无倒置；20 个超重点的比例为 30.3%。
